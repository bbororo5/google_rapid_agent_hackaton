# LaunchPilot 명세 체계

> **Archive notice:** 이 명세는 Phase 0 확정 전에 작성된 초안이다. 신규 리빌드의 현행 기준은 [`docs/rebuild/phase-0-decision-charter.md`](../../rebuild/phase-0-decision-charter.md)다.

문서를 최상위 추상화부터 다시 구성했던 과거 초안이다. 문서 간 충돌이 있으면 [현행 문서 포털](../../../docs/README.md)을 우선한다.

## 경계 원칙

1. **문서 하나 = 질문 하나.** 어떤 문장을 어디에 넣을지 애매하면, 그 문장이 어느 질문의 답인지로 판정한다.
2. **위 문서의 출력이 아래 문서의 입력.** 바로 위 층의 결론만 전제로 받는다. 층을 건너뛰는 참조 금지.
3. **결정은 한 곳에만 산다.** 같은 결정을 두 문서에 서술하지 않는다. 원본 한 곳, 나머지는 링크.

## 층 구성

| 층 | 파일 | 답하는 질문 | 독자 | 상태 |
|---|---|---|---|---|
| L0 | `L0-product-definition.md` | 왜 만들고, 누구의 어떤 문제를 푸는가 | 전원 + 외부 | 초안 |
| L1 | `L1-core-scenarios.md` | 사용자가 언제 와서 무엇을 겪는가 | 전원 | 초안 |
| L2 | `L2-ui-requirements.md` | 그 장면을 어떤 화면과 규칙으로 구현하는가 | 프론트, 디자인 | 초안 |
| L3 | `L3-quality-requirements.md` | 시스템이 무엇을 만족해야 하는가 | 전원 | 초안 |
| L4 | `L4-system-design.md` | 화면 뒤에서 무엇이 어떻게 동작하는가 | 백엔드, AI | 골격 (결정 분류까지) |
| L5 | `L5-quality-operations.md` | 만족하는지 어떻게 아는가 | 전원 | 미작성 |

층 밖: 기계 검증 스키마는 `contracts/`로 관리한다. L4 개방형 결정(O)의 상세 기록은 `L4-decisions/` 하위 폴더에 결정 1건 = 1파일로 둔다 (L4 본문에는 요약만).

**L0가 곧 PRD다.** 별도 PRD를 만들거나 기존 `docs/product/LaunchPilot_PRD.md`를 갱신하지 않는다(중복 금지 원칙). 외부 제출이 필요하면 L0(+L1)를 그대로 사용한다.

**과거 결정의 지위:** 기존 문서들의 결정(가설 카드, 배너, 시각 자료 문법, 에이전트 구성 등)은 자동 승계되지 않는다. 각 층을 작성할 때 그 층의 입력만으로 다시 도출하며, 과거 결정은 후보안 중 하나로만 검토한다.

**L4의 작성 방식:** 아키텍처는 한 번에 그리지 않는다. 결정 지점 추출 → 강제형/개방형/유예형 분류 → 개방형만 후보·트레이드오프 분석(심판: L3 §2 품질 우선순위표) → 조합 검증 → ADR 기록. 분석 깊이는 되돌리기 비용에 비례시킨다.

## 금지 목록 (경계 위반의 대표 사례)

- L0에 화면·컴포넌트·에이전트·기술 스택 언급
- L1에 내부 구현("병렬 호출", "에이전트가") 언급 - 시스템은 블랙박스
- L2에 데이터 저장 방식, 에이전트 구조
- L4에 사용자 여정·제품 당위성 재서술
- L5에 품질 "기준" 신설 - 기준은 L1 인수 기준과 L3의 것이며, L5는 그것의 측정화만
