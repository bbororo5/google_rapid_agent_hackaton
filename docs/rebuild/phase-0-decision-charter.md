# Phase 0 — Product & Evaluation Charter

> 상태: **완료** · 확정일: 2026-08-03

LaunchPilot은 운영 중인 Google ADK 시스템의 마이그레이션이 아니라, 같은 제품 문제를 LangGraph·RAG·Eval 중심으로 다시 푸는 포트폴리오 리빌드다.

## Product decision

1차 사용자는 별도 분석 조직 없이 여러 채널을 운영하는 **소규모 인하우스 마케터**다. 자신의 채널 성과를 직접 관리하는 크리에이터도 같은 작업을 수행하므로 인접 사용자로 포함한다.

> 캠페인 성과가 변했을 때 수집·비교·해석 시간을 줄이고, 다음에 검증할 행동을 근거와 함께 결정하고 싶다.

대표 요청은 단순하다.

```text
“A 캠페인 분석해 줘”
→ Scope → Plan → Execute → Validate → Answer
```

에이전트는 캠페인·기간·목표를 해석하고 필요한 플랫폼 수집, 결정적 계산, 내부 근거 검색을 계획한다. 답변에는 분석·가설·다음 행동뿐 아니라 데이터 기준 시각, 출처, 누락과 한계를 포함한다. 결과를 크게 바꾸는 대상이나 권한이 없을 때만 사용자에게 묻는다.

## Authority boundary

| 에이전트가 수행 | 사용자 승인이 필요 |
| --- | --- |
| 이미 연결된 범위의 읽기·검색·계산·분석 | 신규 OAuth 연결·권한 확대 |
| 필요한 경우 최신 데이터·외부 맥락 조회 | 광고·게시물·외부 메시지 변경 |
| 한 번의 검증과 수정 | 비용·범위가 크게 늘어나는 작업 |

예약 수집은 하지 않는다. 분석 요청 시 근거의 시점과 충분성을 확인해 필요한 데이터만 가져오며, 과거 산출물은 당시 `as_of`와 출처를 보존한다.

## Architecture boundary

- **LangGraph:** 상태, 분기, 도구 호출과 검증 흐름을 소유한다.
- **LangChain:** 모델·도구·Retriever 통합을 필요한 노드에서 사용한다.
- **LLM:** 근거를 해석하지만 수치 계산이나 플랫폼 원본 정규화를 대신하지 않는다.
- **Retrieval:** 정형 수치는 직접 조회·집계하고, 문서는 관련도 검색하며, 관계 확장은 필요성이 측정된 뒤 추가한다.

LangGraph와 LangChain은 양자택일이 아니다. 전체 제어 흐름과 생태계 컴포넌트라는 서로 다른 책임을 가진다. 검색 저장소 선택은 [ADR-0001](adr/0001-retrieval-storage-strategy.md)에서 다룬다.

## Quality contract

| Gate | 통과 조건 |
| --- | --- |
| Tool | 요청과 출처에 맞는 도구를 선택함 |
| Data | 캠페인·기간·수치가 도구 출력과 일치함 |
| Grounding | 주요 주장에 추적 가능한 근거와 시점이 있음 |
| Transparency | 누락·실패·가정과 한계를 공개함 |

Eval은 `대표 사례 → trace → 실패 분류 → 한 가지 변경 → 재평가`를 반복한다. Tool Selection, Numeric Accuracy, Evidence Coverage와 Partial Failure Disclosure는 결정적으로 검사한다. 해석 타당성·과도한 인과 주장·실무 유용성만 LLM judge로 보조한다.

## Scope

포트폴리오에서는 도구 선택, 근거 기반 분석, 상태 흐름과 Eval 개선을 증명한다. 고가용성·분산 실행·예약 동기화·Kafka/CDC·무제한 자기비평·광고 변경 도구는 구현하지 않는다.

## Why this direction

| 질문 | 결정 근거 |
| --- | --- |
| 왜 ADK를 점진적으로 전환하지 않는가? | 운영 트래픽이 없는 포트폴리오이므로 호환성보다 시장에서 요구하는 기술 선택과 평가 경험이 중요하다. |
| 왜 모든 RAG 패턴을 먼저 만들지 않는가? | 복잡성이 품질을 보장하지 않으므로 Baseline과 같은 Dataset에서 개선을 입증한 구성만 유지한다. |
| 왜 요청 시 수집하는가? | 최신성·비용·권한을 사용자가 통제하면서 운영용 예약 파이프라인을 범위에서 제외할 수 있다. |

다음 단계는 플랫폼별 데이터를 하나의 분석 대상으로 묶는 [Phase 1 Domain Model](phase-1-domain-model.md)이다.
