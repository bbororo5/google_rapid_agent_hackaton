| 항목 | 내용 |
|---|---|

## 0. 이 문서의 작성 절차

아키텍처를 한 번에 그리지 않는다. 압박(요구·품질 조건)에서 곧장 단일 윤곽으로 점프하면 첫 안에 앵커링된 사후 합리화가 되기 쉽다. 대신 다음 절차를 따른다.

1. 압박에서 **결정 지점**을 추출한다 (§1) - 후보가 아니라 결정할 문제를 먼저 나열
2. 각 결정을 세 부류로 분류한다 (접두어 F/O/D):
   - **F, Forced (강제형)** - 실질적 대안이 없음. 대안이 비실행인 이유 한 줄로 종결
   - **O, Open (개방형)** - 진짜 선택지가 있음. 후보 2~4개를 놓고 트레이드오프 분석
   - **D, Deferred (유예형)** - 되돌리기 쉬움(투웨이 도어). 기본값을 정하고 진행, 분석하지 않음
3. 개방형 결정은 2단계로 판정한다: **① 관문 - L0 §4 전략 원칙과 강제형(F) 적합성을 합/불로 검사** (불합격 후보는 채점 없이 탈락) → **② 채점 - 통과 후보만 L3 §2 품질 우선순위표를 심판**으로 트레이드오프 판정
4. 선택이 끝나면 **조합 검증**: 결정들을 합쳐놓고 서로 충돌하지 않는지 전체 조립 검사 (§4) - 국소 최적의 합이 전역 최적이 아닐 수 있다
5. 개방형 결정은 각각 `L4-decisions/` 폴더에 결정 기록(선택, 기각 대안, 이유) 1파일로 남긴다
6. 모든 결정에 **되돌리기 비용**을 표기한다. 분석의 깊이는 되돌리기 비용에 비례시킨다 - PoC에서 대부분은 뒤집을 수 있고, 뒤집기 비싼 것(데이터 스키마, 컴포넌트 간 계약)만 신중하게

## 1. 결정 지점 목록

### 1.1 강제형 (대안 없음 - 근거 한 줄씩)

| # | 결정 | 비실행 대안과 그 이유 | 근원 |
|---|---|---|---|
| F1 | 첫 반응은 외부 모델을 기다리지 않는 결정적 경로에서 발행한다 | 모델 대기 후 첫 표시 → 1초 예산 위반 | Q1 |
| F2 | 화면과의 통신은 스트리밍(이벤트 흐름)이다 | 단발 요청-응답 → 진행 표시·실시간 갱신 불가 | CAP-1, Q1 |
| F3 | 분석은 개별 타임아웃을 가진 조사 단계들로 분해된다 | 통짜 호출 → 단계별 실패 감지·부분 답변 불가 | Q1, Q5 |
| F4 | 답변이 화면에 도달하기 전 검증 지점이 존재한다 | 생성 즉시 노출 → 도달 기준 위반 0을 보장할 방법 없음 | Q2, Q3 |
| F5 | 답변의 인용은 구조화된 식별자로 흐른다 | 자유 텍스트만 → 인용 실존의 기계 대조 불가 | Q2 |
| F6 | LLM은 기록(계획·사정·결과)에 쓰기 권한이 없다. 저장은 사용자 동의 액션이 트리거하는 결정적 트랜잭션이다 | LLM이 저장 실행 → 무결성 절대 약속이 확률적이 됨 | Q4 |
| F7 | 수치 계산은 도구(코드)가 하고 LLM은 인용만 한다 | LLM 암산 → 원본 일치를 보장할 방법 없음 | A2, R1 |
| F8 | 진행 표시는 실제 실행 계측 이벤트에서 파생된다 (별도 연출 로직 금지) | 연출 로직 분리 → 구현 변경 시 표시와 실제가 어긋남 (Q7 위반) | Q7 |
| F9 | 모든 지식 문서(트렌드 관찰·노하우)는 출처 식별자와 수집 시점을 필수 필드로 가진다 | 메타데이터 없음 → 출처·시점 표기 불가 | CAP-2 |
| F10 | 모델 접근은 교체 가능한 어댑터를 거친다. 도메인 판단 로직을 코드에 박지 않는다 | 특정 모델 직결·판단 하드코딩 → L0 전략 원칙 위반 | L0 §4 |

## 2. 개방형 결정의 트레이드오프 분석

각 결정은 종결 시 `L4-decisions/` 에 기록하고 이 절에 요약만 남긴다 (상세 근거는 결정 기록이 원본). 남은 순서: O2 → O4 → O5.

### 2.1 O1: 전수 병렬 조사 + 단일 생성 (종결 - L4-decisions/O1)

분석 경로는 조사 3종(지표·트렌드·노하우 - LLM이 아니라 데이터 조회)을 질문과 무관하게 **항상 전부 병렬 실행**하고, 생성 LLM 호출 1회(턴당 유일한 호출)가 대화 기록 + 전체 재료로 답변을 작성해 게이트(F4)를 거친다. 루프는 게이트 재시도(캡 2)뿐, 조사 재회귀는 없다. 즉답은 이 경로를 우회한다. 핵심은 "고르는 판단"과 "다시 고르는 판단"을 만들지 않는 것 - 서랍 3개를 전부 열 수 있는 동안 고르는 기계는 낭비다.

- 기각: (a) 단일+ReAct - 진실성(실패가 사고 루프에 흡수)·응답성(순차 왕복)·형식(만능 프롬프트) 열세. (b) 코디네이터 - 실차이인 "고르기·재회귀"의 이득이 전수 인출 가능한 규모에선 0. 기각이 아니라 유예.
- **확장·축소:** 조사는 단일 규격 + 레지스트리(목록)로 관리. 실행부는 개수를 모른다 - 추가/제거는 목록 편집이 전부.
- **진화 트리거:** 전수 인출이 컨텍스트 용량·비용·Q1 예산을 깨는 순간 코디네이터로 전환(레지스트리 재사용). 질문 유형별 코드 분기는 금지.

## 3. 구조 서술

**(미작성.)** §2의 결정이 끝나면, 강제형 F1~F10과 개방형 선택들을 합쳐 컴포넌트·데이터 흐름·계약 경계를 서술한다. 모든 구조 요소에는 근거가 된 결정 번호(F/O)를 역참조로 단다.

## 4. 조합 검증

**(미작성.)** §3 완성 후: 선택된 결정들이 서로 충돌하지 않는지, L3 §5의 구조 증명 5개가 실제로 성립하는지, L2 CAP-1~9가 모두 이행 가능한지를 전체 조립 상태에서 검사한다. 불가 판정이 나오면 해당 CAP의 개정을 L2로 공식 반송한다.
