# L1. 핵심 시나리오 명세

| 항목 | 내용 |
|---|---|
| 버전 | v1.0 (초안) |
| 작성일 | 2026-07-15 |
| 답하는 질문 | 사용자가 언제 와서 무엇을 요구하고, 시스템은 무엇을 겪게 해야 하는가 |
| 답하지 않는 질문 | 어떤 화면·컴포넌트인가(L2), 내부가 어떻게 동작하는가(L4) |
| 입력 (L0에서 상속) | 세 질문(원인·처방·회고), 약속 3개, "잊는 다수", 집중 카테고리 연예(아이돌), 검증 가설 H1a~H4, 루프 1회전 |

이 문서에서 시스템은 **블랙박스**다. "무엇이 보이고 무엇이 남는가"까지만 서술하고, 그것을 구현하는 화면·구조·기술은 L2 이하에서 정한다.

---

## 1. 요구-동작 의무 목록

사용자의 요구(사용자 언어)와 시스템의 동작 의무(밖에서 관찰 가능한 행동)를 쌍으로 명세한다. 이 목록이 L2·L4가 구현해야 할 것의 원본이고, §4 인수 기준의 뿌리다.

| ID | 사용자 요구 | 시스템 동작 의무 |
|---|---|---|
| R1 | "이 수치가 왜 이런지 알고 싶다" | 원인 후보를 **근거·출처·수집 시점과 함께** 답해야 한다. 답변 속 모든 수치는 원본 데이터와 일치해야 하며, 근거 없는 원인 추정을 말해서는 안 된다 |
| R2 | "그래서 뭘 하라는 건지 알고 싶다" | 다음 행동을 **기간, 대상 지표, 예상 결과(단정값이 아닌 범위)**와 함께 제안해야 한다 |
| R3 | "정한 건 어딘가 남았으면 좋겠다" | 사용자가 동의한 계획은 기록으로 남아야 하고, 언제든 다시 확인할 수 있어야 한다. 동의하지 않은 제안은 기록되지 않아야 한다 |
| R4 | "내가 잊어도 챙겨줬으면 좋겠다" | 계획의 확인 시점이 지난 뒤 사용자가 접속하면, **묻기 전에** 예상과 실제의 비교가 준비되어 있음을 즉시 알 수 있어야 한다 |
| R5 | "AI가 지금 뭘 하는지 알고 싶다" | 응답이 오래 걸리는 분석은 어떤 작업이 진행 중인지 실시간으로 보여야 한다. 즉답 가능한 질문은 지체 없이 답해야 한다 |
| R6 | "모르면 모른다고 해라" | 근거가 부족하면 조언을 만들어내지 않고, 부족하다는 사실과 무엇이 부족한지를 말해야 한다. 참조한 데이터가 오래됐으면 그 시점을 밝혀야 한다 |
| R7 | "내가 말해준 사정은 기억했으면 좋겠다" | 사용자가 알려준 외부 사정(방송 출연, 발행 중단 등)은 사용자 확인을 거쳐 기록되고, 이후의 해석에 반영되어야 한다. 사용자가 말하지 않은 것을 임의로 사실로 기록해서는 안 된다 |

주의: 오른쪽 열에 해법 어휘(특정 화면, 알림 방식, 저장 구조)가 없다. "어떻게"는 전부 L2 이하의 자유다.

## 2. 페르소나와 공통 전제

**페르소나: 김 담당.**
5인 규모 연예 기획사(아이돌 매니지먼트)의 유일한 SNS 담당자. 소속 아티스트는 데뷔 10개월 차 5인조 신인 걸그룹 1팀. Instagram·X·YouTube·TikTok 4개 채널의 기획·촬영·업로드·지표 보고를 혼자 한다. 지표는 매일 보지만, 바쁘면 지난주에 세운 계획을 잊는다 - L0이 정의한 "잊는 다수"의 전형.

**캠페인: "미니 2집 컴백 캠페인" (6주).**
목표: 컴백 콘텐츠의 신규 도달 확대와 챌린지 확산. 현재 문제 상황: 티저 기간인데 쇼츠·릴스 조회수가 2주째 정체이고, 발매곡 챌린지 참여가 기대보다 저조하다.

**데이터 전제 (L0 범위 준수):** 캠페인의 90일치 가상 지표(채널 4개), 연예(아이돌) 카테고리의 트렌드 관찰 표본과 마케터 노하우 표본이 수동 구축되어 있다.

**타임라인:** 장면 1~3 = Day 0 (한 세션), 장면 4 = Day 5, 장면 5 = Day 14. 이 연속 여정이 L0의 "루프 1회전"이다.

## 3. 핵심 장면

각 장면은 (a) 상황 (b) 사용자와 시스템의 주고받음 (c) 장면이 끝났을 때 남는 것, 세 부분으로 서술한다.

### 장면 1. 첫 마주침 - 현황이 먼저 온다 (Day 0)

**(a)** 김 담당이 캠페인 데이터가 연결된 상태에서 처음 접속한다. 목적은 탐색이다: "이게 내 상황을 알긴 하나?"

**(b)** 시스템은 사용자가 입력하기 전에 현황 요약을 먼저 내놓는다: 최근 지표에서 가장 주목할 변화 하나("쇼츠 조회수가 2주째 정체, 다른 지표는 정상 범위")를 결론 문장으로. 김 담당은 이어서 자연어로 묻기 시작할 수 있다.

**(c)** 남는 것: 없음(읽기 전용). 단 "시스템이 내 데이터를 알고 있다"는 첫 신뢰.

### 장면 2. 진단 - "챌린지가 왜 안 퍼지지?" (Day 0)

**(a)** 김 담당이 묻는다: "챌린지 참여가 왜 이렇게 저조해?"

**(b)** 분석이 도는 동안 무엇을 조사 중인지 실시간으로 보인다(R5). 답은 결론부터 온다: "챌린지 음원 구간이 현재 유행 문법과 어긋나는 것이 주원인 후보입니다." 이어서 근거가 문장으로 붙는다: "지금 아이돌 챌린지에서 확산되는 형식은 포인트 안무 3초 반복형인데(트렌드 관찰, 5일 전 수집 기준), 우리 챌린지 구간은 15초 연속 안무입니다. 유사 규모 신인 그룹의 참여형 콘텐츠 노하우 기준으로도 진입 장벽이 높습니다." 수치를 물으면 원본 데이터와 일치하는 값으로 답한다(R1). 김 담당이 근거가 약한 주제("팬덤 여론이 어떤데?")를 물으면, 시스템은 지어내지 않고 "그 데이터는 없다"고 답한다(R6).

**(c)** 남는 것: 원인에 대한 공유된 이해. 기록물은 아직 없다.

### 장면 3. 계획 합의 - 다음 행동이 기록으로 남는다 (Day 0)

**(a)** 김 담당: "그럼 어떻게 바꿔볼까?"

**(b)** 시스템이 다음 행동을 제안한다: "챌린지 구간을 포인트 안무 3초 반복형으로 재편집한 버전을 병행 발행. 2주간, 챌린지 참여 수 기준, 현재 대비 +30~60% 예상. 근거: 위 트렌드 관찰 + 노하우 표본." 기간·지표·예상 범위가 빠짐없이 담긴다(R2). 김 담당이 동의하면 이 계획은 기록으로 남고 확인 시점(Day 14)이 함께 정해진다. 동의하지 않고 "다르게 하자"고 하면 수정 제안을 거쳐 동의된 버전만 남는다(R3).

**(c)** 남는 것: **합의된 계획 1건** - 내용, 기간, 대상 지표, 예상 범위, 근거, 확인 시점. 이 캠페인에서 언제든 다시 볼 수 있다.

### 장면 4. 지나가는 말 - 외부 사정이 접수된다 (Day 5)

**(a)** 다른 질문을 하던 중 김 담당이 지나가듯 말한다: "다음 주에 음악방송 첫 출연이라 이번 주말 자체 콘텐츠는 못 올릴 듯."

**(b)** 시스템이 되묻는다: "방송 출연과 주말 발행 공백, 진행 중인 계획의 해석에 반영하도록 기록해둘까요?" 김 담당이 좋다고 하면 기록되고, 싫다고 하면 기록되지 않으며 같은 세션에서 다시 조르지 않는다(R7).

**(c)** 남는 것: 계획에 딸린 외부 사정 기록 1건("Day 5: 음방 첫 출연 예정, 주말 자체 발행 공백").

### 장면 5. 결과 확인 - 잊었지만 루프가 닫힌다 (Day 14)

**(a)** 김 담당은 음방 준비로 정신이 없어 계획을 잊었다. 9일 만에 접속한다.

**(b)** 접속하자마자, 묻기 전에, 확인할 결과가 준비되어 있음이 보인다(R4): "합의한 계획의 확인 시점이 지났습니다. 예상 +30~60% / 실제 +18%." 이어지는 해석에는 Day 5의 외부 사정이 반영된다: "주말 발행 공백(음방 출연 주)이 있었던 것을 감안하면, 공백 기간을 제외한 참여 증가율은 +34%로 예상 범위 안입니다. 재편집 버전 자체는 유효했다고 볼 수 있습니다." 김 담당이 "그럼 다음은?"이라 물으면 장면 3과 같은 방식으로 후속 계획이 제안되고, 동의 시 이전 계획과 이어진 기록으로 남는다.

**(c)** 남는 것: 결과가 기록된 계획 1건(예상 대비 실제, 외부 사정 반영 해석) + 후속 계획 1건. **L0의 루프 1회전이 여기서 완결된다.**

## 4. 인수 기준

각 장면이 "성립했다"의 판정 문장. L0 검증 가설과의 연결을 함께 표기한다.

| # | 인수 기준 | 장면 | 검증 가설 |
|---|---|---|---|
| A1 | 사용자 입력 이전에 데이터 기반 현황 요약이 결론 문장으로 제시된다 | 1 | H2 |
| A2 | 진단 답변에 근거·출처·수집 시점이 포함되고, 인용 수치가 원본 데이터와 일치한다 | 2 | H1a, H3 |
| A3 | 근거가 없는 질문에 "없다/모른다"가 답으로 나오고, 조언이 생성되지 않는다 | 2 | H3 |
| A4 | 오래 걸리는 분석 중 진행 상황이 실시간 표시되고, 총 응답이 수십 초 이내다 | 2, 3 | H4 |
| A5 | 제안된 계획에 기간·대상 지표·예상 범위·근거가 전부 포함된다 | 3 | H1a |
| A6 | 동의한 계획만 기록되고, 기록된 계획을 이후 세션에서 다시 볼 수 있다 | 3 | H2 |
| A7 | 외부 사정은 사용자 확인 후에만 기록되고, 거절 시 같은 세션에서 재요청하지 않는다 | 4 | H2 |
| A8 | 확인 시점 경과 후 접속 시, 요청 없이 예상-실제 비교가 준비되어 있다 | 5 | H2 |
| A9 | 결과 해석에 기록된 외부 사정이 실제로 인용·반영된다 | 5 | H1a, H2 |
| A10 | 후속 계획이 이전 계획의 결과와 연결된 기록으로 남는다 | 5 | H2 |

1차 검증(개발팀 도그푸딩)은 이 장면 대본을 그대로 수행하며 A1~A10을 체크리스트로 판정한다. H1b(마케터 유용성)는 같은 대본을 마케터가 수행할 때 답변 내용의 평가로 확장된다.

## 5. 이 문서에서 다루지 않는 것

- 장면 1 이전(가입·데이터 연결 절차) - 검증 범위 밖, 데이터는 준비된 상태에서 시작
- 캠페인이 여러 개일 때의 여정 - 루프 1회전 검증에 불필요
- 계획을 여러 개 병행하는 여정 - 동일
- 콘텐츠 제작물(문구·영상 기획안) 산출 - L0 범위의 루프에 필수 아님
