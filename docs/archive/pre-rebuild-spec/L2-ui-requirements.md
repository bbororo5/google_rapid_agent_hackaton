## 1. 정보 구조: 화면 3개

L1의 장면들이 요구하는 표면은 세 성격이다: 묻기 전에 보이는 곳(장면 1·5), 주고받는 곳(장면 2~4), 남은 기록을 다시 보는 곳(R3). 이를 화면 3개로 배치한다.

| 화면 | 성격 | 근거 |
|---|---|---|
| **홈** | 접속하면 가장 먼저 보이는 화면. 현황 요약과, 확인 시점이 지난 계획의 결과 준비 알림이 놓인다 | 장면 1(현황이 먼저), 장면 5·A8(묻기 전에 보임) |
| **대화** | 유일한 입력 표면. 질문·답변·진행 표시·계획 합의가 모두 이 흐름 안에서 일어난다 | 장면 2~4, R5 |
| **계획 기록** | 합의된 계획과 그 결과가 쌓이는 목록. 읽기 전용이며, 계획의 생성·수정은 대화에서만 일어난다 | R3·A6("언제든 다시 확인"), A10(계획 간 연결) |

PoC 전제: 캠페인 1개 고정(L1 §5), 대화는 단일 스레드 1개. 캠페인 전환, 대화 여러 개, 계정 관리는 이 문서의 범위 밖이다.

## 2. 장면 → 화면 워크스루

**장면 1 (Day 0):** 접속 → 홈에 현황 요약이 이미 렌더링되어 있다(결론 문장 + 관련 지표). 요약에서 대화로 이어지는 진입점 1개("자세히 물어보기"). 사용자는 홈을 건너뛰고 바로 대화로 갈 수도 있다.

**장면 2 (Day 0):** 대화 화면에서 질문 입력 → 분석형 응답이면 진행 표시(§6)가 먼저 나타난다 → 완료되면 답변이 결론 문장부터 표시된다(§4). 근거·출처·시점은 답변 문장 안에 있다.

**장면 3 (Day 0):** 대화 중 시스템이 계획을 제안하면, 답변 아래 **동의 액션**([이대로 진행] [수정 요청] [아니오])이 붙는다. [이대로 진행] 선택 시에만 계획이 기록되고, 대화에는 "기록됨 + 확인 시점" 확인 문장이 남으며, 계획 기록 화면에 항목이 생긴다. [수정 요청]은 자유 텍스트로 이어진다.

**장면 4 (Day 5):** 사용자의 발화에서 외부 사정이 감지되면, 대화 안에 확인 질문 + [기록] [넘어가기] 액션이 나타난다. [기록] 시 해당 계획 항목에 사정이 추가되고, [넘어가기] 시 같은 세션에서 같은 건을 다시 묻지 않는다(A7).

**장면 5 (Day 14):** 접속 → 홈 최상단에 결과 준비 알림("계획 확인 시점 경과 - 예상 +30~60% / 실제 +18%")이 현황 요약보다 우선 배치된다. 알림 선택 시 대화 화면으로 이동하며 결과 비교 답변(예상-실제 시각물 + 외부 사정 반영 해석)이 시작된다. 후속 계획 제안·동의는 장면 3과 동일한 인터랙션이다.

## 3. 화면별 상태

| 화면 | 상태 | 표시 |
|---|---|---|
| 홈 | 기본 | 현황 요약 |
| 홈 | 확인 시점 경과 계획 존재 | 결과 준비 알림이 요약보다 상단. 알림은 삭제되지 않고 결과 확인 대화 진입 시 해소 |
| 홈 | 데이터 이상 (지표 미적재 등) | 오류 상태 문구. 가짜 요약을 만들지 않는다 |
| 대화 | 입력 대기 / 즉답 / 분석 중 / 답변 완료 / 부분 실패 | §6 참조. 부분 실패 시 어느 조사가 안 됐는지 문장으로 고지(R6) |
| 대화 | 외부 모델 장애 | 분석 응답 불가를 정직하게 고지하고, 가능한 것(기록 열람, 단순 조회)만 안내. 가짜 답변으로 메우지 않는다 |
| 계획 기록 | 0건 / N건 | 0건이면 "아직 합의된 계획 없음" + 대화 진입점. N건이면 최신순, 각 항목에 상태(진행 중 / 확인 시점 경과 / 결과 기록됨) |

## 4. 답변 표현 규칙

R1·R2·R6이 정한 내용 의무를 화면 형태로 옮긴 규칙이다.

**해석 원칙: 이 규칙들의 주어는 시스템이다.** 답변 생성은 외부 LLM에 의존하며 모델은 어떤 규칙이든 어길 수 있다. 따라서 아래 규칙은 "모델이 항상 지킨다"는 약속이 아니라 **"위반한 출력은 화면에 도달하지 않는다"**는 약속이다(도달 전 검증, 위반 시 재시도 또는 강등 - CAP-8).

1. **결론 우선.** 모든 분석 답변은 결론 한 문장으로 시작한다. 차트·수치·상세는 그 아래.
2. **근거는 문장 안에.** 출처와 수집 시점은 별도 패널이나 클릭해서 펼치는 요소가 아니라 답변 문장에 직접 쓴다: "~입니다(트렌드 관찰, 5일 전 수집 기준)". 이유: R1의 근거는 사용자가 안 눌러도 전달되어야 하며, PoC에서 검증할 것은 내용이지 탐색 UI가 아니다. 클릭 깊이는 전 화면에서 최소화한다.
3. **시각물은 2종으로 제한.** (a) **지표 추이** - 시간 흐름 위에 계획 시작·외부 사정 같은 사건 표시를 찍은 선형 차트(장면 2·5). (b) **예상-실제 비교** - 예상 범위와 실제값의 대비(장면 5, A8·A9). 두 시각물 모두 결론 문장 없이 단독으로 나올 수 없다. PoC에서 이 이상의 차트 종류는 만들지 않는다.
4. **수치는 원본 그대로.** 답변 속 수치는 반올림 표기 규칙만 적용하고 임의 가공하지 않는다(A2의 화면 측 책임).
5. **"모른다"의 형태.** 근거 부족 답변은 사과나 얼버무림 없이 세 요소로 구성한다: 없다는 사실, 무엇이 없는지, 대신 할 수 있는 것. 예: "팬덤 여론 데이터는 없습니다. 현재 표본은 지표와 트렌드 관찰뿐입니다. 참여 지표 기준으로는 답할 수 있습니다."
6. **예상은 항상 범위로 표기한다.** 단정값 표기는 화면 규칙 위반이다(R2).

## 5. 인터랙션 규칙

1. 입력은 자유 텍스트 단일 채널. 명령어·폼 없음.
2. 시스템이 사용자에게 결정을 요구하는 경우는 두 가지뿐이다: 계획 동의(장면 3)와 외부 사정 기록 확인(장면 4). 둘 다 대화 흐름 안의 액션 버튼이며, 무응답이면 아무것도 기록되지 않는다.
3. 거절·무시에 재촉하지 않는다. 같은 세션 내 동일 건 재질문 금지(A7).
4. 계획 기록 화면은 읽기 전용. 항목 선택 시 해당 계획의 전체 내용(합의 내용, 근거, 외부 사정, 결과)이 보이고, "이 계획에 대해 물어보기"로 대화에 컨텍스트를 실어 진입할 수 있다.

## 6. 대기의 연출 (R5·H4의 화면 책임)

1. **즉답과 분석의 구분.** 조회성 질문은 진행 표시 없이 즉시 답한다. 분석형만 진행 표시를 쓴다 - 표시 자체가 "깊은 분석 중"의 신호가 되도록.
2. **진행 표시의 내용.** 회전 아이콘이 아니라 무엇을 하는 중인지의 문장 목록이다: "지표 조회 중 → 완료", "트렌드 표본 대조 중 - 유사 사례 2건 발견". 발견 수가 갱신되면 실시간 반영한다. 완료된 단계는 남아서 답변의 조사 내역이 된다.
3. **첫 반응 시간.** 질문 제출 후 1초 내에 진행 표시의 첫 줄이 나타나야 한다. 침묵 구간 금지. 설계 제약: 이 첫 반응은 외부 모델 응답을 기다리지 않고 시스템이 자체 생성해야 한다 - 외부 API 지연과 무관하게 지켜지는 유일한 방법이다.
4. **부분 실패의 표시.** 일부 조사가 실패·시간 초과되면 그 단계가 미완료로 남고, 답변 첫머리에 한계가 문장으로 붙는다: "트렌드 대조는 이번에 완료하지 못했습니다. 지표만 보면 ~"
5. **검증 재시도의 표시.** 모델 출력이 표현 규칙·근거 검증에 걸려 재생성되는 경우, 침묵이 늘어나는 대신 진행 표시에 "답변 점검 중" 단계로 나타난다.

## 7. L4에 요구하는 능력 (Capability Requirements)

이 화면 명세가 암묵적으로 전제하는 백엔드 능력의 명시 목록. L3의 입력이며, L4가 이 중 하나라도 만족 불가로 판정하면 해당 화면 규칙의 개정을 공식 반송한다.

| ID | 요구 능력 | 걸린 화면 규칙 |
|---|---|---|
| CAP-1 | 분석 진행 단계를 실시간 이벤트로 스트리밍 (단계명, 상태, 발견 수) | §6.2, §6.3 |
| CAP-2 | 모든 답변 근거에 출처 식별자와 수집 시점 메타데이터 | §4.2 |
| CAP-3 | 분석형 응답 완료가 일관되게 수십 초 이내 | §6, H4 |
| CAP-4 | 계획의 영속 저장 + 확인 시점 경과 여부의 상태 판정 | §1 계획 기록, §3 홈 상태 |
| CAP-5 | 조사 단계별 부분 실패의 식별과 통지 | §6.4, §3 대화 상태 |
| CAP-6 | 외부 사정 기록과 이후 분석에의 반영 | 장면 4·5, A9 |
| CAP-7 | 예상-실제 비교에 필요한 데이터 (예상 범위 저장, 실제치 계산) | §4.3(b), A8 |
| CAP-8 | 모델 출력의 도달 전 검증: 표현 규칙 위반·근거 불일치 출력을 화면 도달 전에 차단하고 재시도 또는 강등 | §4 해석 원칙 |
| CAP-9 | 외부 모델의 장애·시간 초과 감지와 상태 신호 (부분 실패 / 전면 장애 구분) | §3 대화 상태, §6.4 |

CAP-3의 해석: 외부 LLM API의 지연 변동은 통제 밖이므로 "항상"은 약속 불가다. 요구 수준은 **반복 실행의 90% 이상이 예산 내, 초과 시 CAP-9의 강등 경로 발동**으로 정의한다.

## 8. 화면 수준 인수 기준

L1의 A 중 화면이 책임지는 부분의 구체화. 도그푸딩 시 이 문장으로 판정한다.

| # | 기준 | 원 기준 |
|---|---|---|
| U1 | 접속 후 첫 화면에서 추가 조작 없이 현황 요약(또는 결과 준비 알림)이 보인다 | A1, A8 |
| U2 | 분석 답변의 근거·출처·시점이 클릭 없이 본문에서 읽힌다 | A2 |
| U3 | 질문 제출 1초 내 첫 반응이 나타나고, 분석 중 단계 문장이 갱신된다 | A4 |
| U4 | 계획 동의 전에는 계획 기록 화면에 아무것도 생기지 않는다 | A6 |
| U5 | 시각물 2종 외의 차트가 존재하지 않고, 모든 시각물에 결론 문장이 붙어 있다 | A2, A5 |
| U6 | 거절한 확인 요청이 같은 세션에서 다시 나타나지 않는다 | A7 |
| U7 | 결과 준비 알림이 현황 요약보다 상단에 배치된다 | A8 |

## 9. 다루지 않는 것

- 비주얼 디자인, 반응형·모바일 대응 (PoC는 데스크톱 1해상도)
- 온보딩·가입·데이터 연결 화면 (L1 §5 제외 상속)
- 캠페인 전환·대화 목록·설정 화면
- 접근성 기준 (운영 단계 과제로 이월)
